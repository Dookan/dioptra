# Standards mapping

> **Status: IN_PROGRESS — P0 controls implemented 2026-08-17; the rest grow
> with their phase.**
> Format: OWASP ASVS 4.0.3 control → requirement → implementation pointer.
> The platform targets ASVS **L2** for itself.

| Control | Requirement | Implementation |
|---|---|---|
| V2.2 Authenticator lifecycle | Rate limiting / lockout on repeated failures | `authenticate()` counter + capped backoff, `423` with `Retry-After` — `backend/app/auth/service.py` — IMPLEMENTED (P0) |
| V2.4 Credential storage | Passwords hashed with a memory-hard function | Argon2id (19 MiB, t=2, p=1) with transparent rehash — `backend/app/auth/passwords.py` — IMPLEMENTED (P0) |
| V3.3 Session termination | Short-lived tokens, revocable refresh | 15-min JWT + rotating refresh, reuse revokes the family; logout and password change revoke every refresh token, and `password_changed_at` invalidates every access token issued before the change, so no token survives a credential change — `backend/app/auth/{tokens,service,deps}.py` — IMPLEMENTED (P0) |
| V3.4 Cookie-based session | Session token in an HttpOnly, Secure, SameSite cookie | refresh cookie set in `backend/app/auth/router.py`; the access token never leaves memory — IMPLEMENTED (P0) |
| V4.1 Access control | Deny by default, enforced server-side per role | `require_roles()` dependency; stale-role tokens rejected — `backend/app/auth/deps.py` — IMPLEMENTED (P0); triage verdicts and report edit/sign are `AnalystUser` only, the developer AND the admin get 403 + an `authz.denied` row — `backend/app/workflow/router.py`, `backend/app/reports/router.py` — IMPLEMENTED (P2); stage transitions check the role per stage before the gate (`backend/app/workflow/stages.py::LEAVE_ROLES`), the test plan, the diagram text, the cases and their approval are `DeveloperUser` only — IMPLEMENTED (P3); the E6 test file is `DeveloperUser` only and writable only AT E6 (or at E7 for a reopened function), and running the E7 verification and reopening a failed design are `DeveloperUser` only — `backend/app/workflow/{authoring,verify}.py` — IMPLEMENTED (P4); refreshing the vulnerability mirror is admin or analyst only and the audit-log read returns only the caller's own rows unless the caller is the admin — `backend/app/inventory/router.py`, `backend/app/audit/router.py` — IMPLEMENTED (P5) |
| V5.3 Output encoding | Untrusted data escaped at every render | report engine: Jinja2 autoescape on every template, Markdown escaping filter, WeasyPrint URL fetcher restricted to the template's own assets — `backend/app/reports/engine.py` — IMPLEMENTED (P1); analyst-authored report sections escaped in every format and the findings screen renders audited values as text nodes only — `backend/app/reports/versions.py`, `frontend/src/screens/findings-screen.tsx` — IMPLEMENTED (P2); the E6 scaffold escapes every developer title and every audited identifier at the generator's boundary before it becomes an identifier, a string literal or a comment, and the stored test file is rendered as text — `backend/app/workflow/scaffold/text.py` — IMPLEMENTED (P4) |
| V7.1 Log content | No secrets in logs; auditable security events | append-only audit log enforced by DB triggers refusing UPDATE, DELETE **and** TRUNCATE, asserted against real PostgreSQL in the `migrations` CI job — `backend/app/audit/`, `backend/alembic/versions/0001_foundations.py` — IMPLEMENTED (P0); every triage verdict (`finding.verdict.<verdict>`), report save (`report.edit`), signature (`report.sign`), stage transition (`stage.advance`) and test-plan save (`testplan.save`) is a row carrying the mandatory written justification, every E5 write (`design.diagram.edit`, `design.cases.save`, `design.cases.approve`) a row with actor and function, every E6 save (`tests.save`) the same, and E7 writes `verification.run` and `verification.reopen` (the latter with its mandatory written reason) — `backend/app/workflow/{triage,stages,test_plan,design,authoring,verify}.py`, `backend/app/reports/versions.py` — IMPLEMENTED (P2–P4); the inventory writes `vulndb.sync.request` / `vulndb.import.request` (actor, written reason) and the worker `vulndb.sync` / `vulndb.import` with the outcome, and the trail is READABLE through `GET /api/v1/audit` scoped by role — `backend/app/inventory/sync.py`, `backend/app/audit/router.py` — IMPLEMENTED (P5) |
| V7.4 Error handling | Generic messages, no stack traces to clients | `AppError` hierarchy + handlers returning `{code, message_key}` — `backend/app/core/errors.py`, `backend/app/main.py` — IMPLEMENTED (P0) |
| V10.3 Deployed application integrity | No code from untrusted sources at runtime | CSP `default-src 'self'` on API and nginx; `scripts/no_cdn_check.py` fails the build on any external reference — IMPLEMENTED (P0) |
| V12.1 File upload | Size/type limits, no path traversal | ZIP ingest: declared-length and real-size caps, entry-count cap, decompression-ratio cap, streamed byte counter, zip-slip and symlink rejection, per-analysis jail — `backend/app/ingest/archive.py`; the 200 MiB body cap is enforced first by nginx (`docker/nginx.conf`, also bounds chunked bodies) — IMPLEMENTED (P1); the vulnerability-dump import: kind by extension, declared and streamed byte caps, spooled by the API and parsed only by the worker with entry-count / per-entry / ratio caps and entry names ignored — `backend/app/inventory/{sync,importers}.py` — IMPLEMENTED (P5) |
| V14.2 Dependency management | Components from trusted sources, up to date | `scripts/license_gate.py` (free licences, own checker) + blocking `dependency-vulnerabilities` (`npm audit --audit-level=high`) + advisory `dependency-currency` + pinned `uv.lock` / `package-lock.json` — IMPLEMENTED (P0); for the AUDITED systems, the software inventory correlates every SBOM component against the local OSV + NVD mirror and flags outdated ones — `backend/app/inventory/` — IMPLEMENTED (P5) |
| V12.6 SSRF protection | Server never fetches an attacker-chosen internal URL | git URL ingest: HTTPS only, no credentials, host resolved and rejected when private / loopback / link-local; clone runs in the worker with redirects disabled — `backend/app/ingest/git_source.py` — IMPLEMENTED (P1) |
| V1.14 Configuration architecture | Untrusted code executes only inside a hardened, isolated sandbox | one ephemeral container per verification attempt: `--network none --read-only --cap-drop ALL --security-opt no-new-privileges`, non-root, memory = memory-swap, `--cpus`, `--pids-limit`, a 120 s timeout that kills the NAMED container, exactly one writable mount (the per-attempt directory), no Docker socket, nothing of the audited project installed, and only three declared result files read back capped and parsed as data — `backend/app/sandbox/`, `docker/sandbox.Dockerfile`; nine escape probes run with the shipped argv and all negative (`docs/threat-model.md` → Sandbox escape tests) — IMPLEMENTED (P4) |
| V14.4 HTTP security headers | Hardening headers on every response | `SECURITY_HEADERS` middleware + `docker/nginx.conf` — IMPLEMENTED (P0) |
