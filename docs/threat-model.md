# Threat model

> **Status: FINAL for v1.0.0 (2026-09-22) — every row is built: P0 (Auth, Audit log, Supply chain), P1 (ZIP ingest, git URL ingest, Finding snippets, Analysis containers, SBOM generation), P2 (Report editing), P3 (Flow diagrams, Case design), P4 (Test scaffolds and files, Test sandbox), P5 (Inventory rendering, Vulnerability DB sync, VEX statements, Audit log read, Report annexes). The residual risks below were reviewed at the close; each keeps its revisit trigger, and the `DROP TRIGGER` residual is resolved by the owner/runtime role split.**

The central premise: **the audited system is the attacker.** Hostile code is
parsed (analysis), rendered (findings, reports) and executed (tests).

## Sandbox escape tests (P4, day 17)

> **Status: RUN 2026-09-22, all negative.** The plan makes this the release
> blocker: a positive escape test means no release, fixed even if it consumes
> the whole buffer. They live in `backend/tests/test_sandbox_live.py`, marked
> `sandbox`, and are skipped only where Docker or `dioptra-sandbox:latest` is
> absent.

Every probe runs with the argv `app/sandbox/executor.py::command` ships, with
the command swapped — and with `--user`, which the fixture sets to the test
process's own uid so the container can write the attempt directory it created
(both values are non-root; the shipped images run as 10001).

**Each probe was checked to be ATTRIBUTABLE**: it fails under the shipped
flags AND succeeds when the flag it targets is removed. That check is not
ceremony. Three earlier probes passed for free and proved nothing — `capsh`
is not installed in the image, so the capability probe exited non-zero
whatever the capability set; `mount -t proc` is refused even when privileged,
because `/proc` is already mounted; and a fork bomb written with literal
backslash-n died of a `SyntaxError` before forking anything. A negative
control that cannot go positive is not evidence.

| Test | Command inside the container | Shipped flags | Flag removed |
|---|---|---|---|
| Outbound network | `socket.create_connection(('1.1.1.1',53))` | refused | succeeds without `--network none` |
| Write outside the workspace | `touch /etc/dioptra-pwned` | refused | succeeds as root without `--read-only` |
| Write into the image's own tree | `touch /usr/local/bin/dioptra-pwned` | refused | succeeds as root without `--read-only` |
| Write to `/proc` | `echo 1 > /proc/sys/kernel/core_uses_pid` | refused | succeeds privileged |
| Escape via the Docker socket | `test -S /var/run/docker.sock` | absent | succeeds when the socket is bind-mounted |
| Gain capabilities | `grep '^Cap(Prm\|Eff\|Bnd):' /proc/self/status` — every set must be all zeros | all zeros | non-zero without `--cap-drop ALL` |
| Keep the right to gain privileges | `grep 'NoNewPrivs:\t0' /proc/self/status` | `NoNewPrivs: 1` | `0` without `no-new-privileges` |
| Become root | `os.setuid(0)` | refused | succeeds as `--user 0:0` |
| Mount a filesystem | `mount -t tmpfs tmpfs /mnt` | refused (exit 32) | succeeds privileged |
| Fork bomb | `os.fork()` until `OSError`, then `exit 7` | **exit 7** — a fork WAS refused | runs to completion with a high `--pids-limit` |
| Memory balloon | 64 MiB chunks until death | killed | — |
| CPU spin (a test that never returns) | `while True: pass` | the named container is killed at the timeout, in under 90 s | **a raw `subprocess.run` leaves it spinning** — the timeout kills the docker CLIENT, not the container |

Exit 7 is the fork-bomb probe's own `OSError` branch, so it can only happen
when a fork was actually refused: a missing binary or a syntax error gives 1
or 2. The CPU-spin test goes through `executor.run` rather than a command
swap, because what stops an endless loop is the named container plus the
`docker kill` hook — verified by watching a raw invocation still spin two
minutes later.

Three further properties are asserted by the same suite: a canary written into
the attempt directory appears in none of the three files read back nor in the
stderr; the run directory no longer exists afterwards; and a thorough suite on
a real module reaches 100 % statements with no partial branch while a
one-assertion suite leaves mutants alive — the plan's own release criterion,
measured rather than asserted.

### PHP image (phase 7a, 2026-09-23) — RUN, all negative, all attributable

The same discipline, re-run against `dioptra-sandbox-php:latest`, because a
second image is a second claim. The flags are shared by construction
(`executor.command` is one function; only the image string differs, chosen by
`executor.image_for` from the scaffold's runner), but P4's lesson is that a
negative control which cannot go positive is not evidence.

**Every probe had to be re-expressed for what this image actually has**, and
that check came first: it has **no `python3`** — four of the wave-1 probes use
it and would have failed for the wrong reason — **no `pcntl`** extension, and
no `sockets` extension. It does have `php` with `posix`, stream functions, and
`perl` from the Debian base. `memory_limit` is 512 M in its php.ini, so a
balloon would hit PHP's own limit rather than the container's `--memory`: the
probe lifts it to `-1` first, which is what makes it attributable.

| Probe | Command inside the container | Shipped flags | Flag removed |
|---|---|---|---|
| Outbound network | `php -r fsockopen('1.1.1.1', 53, …)` | refused (1) | **succeeds (0)** without `--network none` |
| Write outside the workspace | `touch /etc/dioptra-pwned` | refused (1) | **succeeds** as root without `--read-only` |
| Write into the image's own tree | `touch /usr/local/bin/dioptra-pwned` | refused (1) | **succeeds** as root without `--read-only` |
| Write to `/proc` | `echo 1 > /proc/sys/kernel/core_uses_pid` | refused (2) | **succeeds** privileged |
| Escape via the Docker socket | `test -S /var/run/docker.sock` | absent (1) | **succeeds** when the socket is bind-mounted |
| Gain capabilities | every `Cap(Prm/Eff/Bnd)` set must be all zeros | all zeros (1) | **non-zero** without `--cap-drop ALL` |
| Keep the right to gain privileges | `grep 'NoNewPrivs:\t0' /proc/self/status` | `NoNewPrivs: 1` (1) | **`0`** without `no-new-privileges` |
| Become root | `php -r posix_setuid(0)` | refused (1) | **succeeds** as `--user 0:0` |
| Mount a filesystem | `mount -t tmpfs tmpfs /mnt` | refused (32) | **succeeds** privileged |
| Fork bomb | `perl` forking until `fork()` returns undef, then `exit 7` | **exit 7** — a fork WAS refused | **exit 0** with `--pids-limit 4000` |
| Memory balloon | `php -r` with `memory_limit=-1`, 64 MiB chunks | killed | not attributability-checked: removing `--memory` would balloon the HOST |

Exit 7 is the fork probe's own `fork() === undef` branch, so it can only happen
when a fork was actually refused — a missing binary or a syntax error gives a
different code. The suite lives in `backend/tests/test_sandbox_live.py`
(`test_the_php_sandbox_refuses_every_escape` and the two named probes), behind
the same `sandbox` marker, skipped where the PHP image is absent.

| **A finding leaves mandatory E3 review because of a DIRECTORY NAME the audited tree chose.** `analysis/third_party.py` classifies by path segment (`vendor`, `node_modules`, `site-packages`, …), and every path comes from the audited tree. A team that puts its own source under a directory called `vendor/` takes those findings out of the queue the E3 gate counts — and `record_verdict` then REFUSES a verdict on them (422 `finding_not_triageable`), so an analyst who spots the trick cannot adjudicate them either | What bounds it is that **the document is unaffected**: the finding is still stored, still printed in every export, still counted by the executive summary, still carried by the inventory and the VEX (proven by RENDERING: `backend/tests/test_third_party.py::test_dependency_findings_are_still_listed_and_still_reported` exports a dependency finding in all four formats and asserts its path is in the HTML and the Markdown — the claim used to rest on a reading of the code, which the invariant checker called on 2026-09-23). So nothing is hidden from the reader of the report; what changes is only whether the analyst was REQUIRED to write a justification about it. The alternative — classifying by provenance rather than by name — means trusting the lockfiles, which are equally the audited tree's. Decided by `mmarin` 2026-09-23 against a real application where the rule removed 430 of 687 findings from the queue | An E3 pass used as evidence OUTSIDE the institution (the same trigger the forgeable-E7-verdict residual carries), or the first audited tree found to declare its own source under a dependency directory name |
| **The audited code can forge its own E7 verdict.** The tests execute in the same container as the runner that reports on them, as the same user. The artefacts are now produced on the container's own tmpfs and copied into the shared mount only after every runner process has exited (`docker/sandbox/run-*.sh`), which removes the easy tricks — rewriting `junit.xml` from an `atexit` hook after pytest flushed it, or deleting the coverage data so a planted document survives. It does not make the verdict tamper-proof: code that runs at all can write to that tmpfs before the copy | Real integrity would mean producing the verdict outside the container the code runs in — a second container, or re-deriving it from a stream the audited code cannot reach. That is a redesign of E7, not a day-17 fix. What bounds the damage is who is harmed: a project that forges a pass deceives its OWN report, and the analyst still signs it. Absence is no longer a pass — a missing or unparseable document is `ERRORED`, never a verdict (`workflow/verify.py`), so forging now requires producing a plausible document rather than removing one | The P5 self-audit, or the first time an E7 pass is used as evidence outside the institution |
